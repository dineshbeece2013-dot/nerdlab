Docker: The Same App Everywhere

What is Docker?

An app is never just the code. It needs a particular version of a language, a handful of libraries, some settings, a folder in the right place. Install it on a second computer where any one of those differs and it behaves differently — or refuses to start. That is the oldest complaint in software: it works on my machine.

Docker ends the argument by shipping the machine with the app. You write down everything the app needs in a file called a Dockerfile. Docker follows that file and packs the app, its language, and its libraries into one sealed bundle called an image. Anyone who runs that image gets exactly what you had — on a laptop, a server, or a cloud, identically.

What you learned

  • A Dockerfile is a recipe. Every line is a step, and Docker follows them in order.
  • Order decides speed. Copy the dependency list before the source, and installing is skipped on most rebuilds.
  • Each step is a saved layer. Docker reuses a layer until something it depends on changes — then everything after it is redone.
  • Say what runs and where. Without a start command the image is a box nobody can open.
