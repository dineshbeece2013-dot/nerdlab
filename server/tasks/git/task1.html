Git: Trying Things Without Fear

What is Git?

Imagine writing an essay and saving copies as you go: essay.doc, essay-final.doc, essay-final-REAL.doc. It works, badly. You cannot remember what changed between them, and you certainly cannot let a friend edit one without losing track of which is which.

Git is the tool that does this properly. It keeps the history of a folder: every time you tell it to, it takes a snapshot you can return to later. That one idea buys you two things. You can always get an earlier version back. And you can try something risky on the side, knowing the version that works is untouched.

Almost every software team on earth uses it, which is why it is the first thing anyone teaches you.

What you learned

  • A commit is a snapshot you can return to. Nothing is saved to history until you commit it.
  • Staging is choosing what goes in the snapshot. git add selects; git commit saves.
  • A branch is a separate line of work. Experiment there and the working version stays untouched.
  • Merging brings the work back once you are happy with it.
