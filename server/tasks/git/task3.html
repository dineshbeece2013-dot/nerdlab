Git: When Two People Edit One File

What a conflict actually is

Git merges most work automatically. Two people editing different files, or different parts of one file, is a solved problem — you will never even see it happen.

A conflict is the one case it refuses to guess: the same lines of the same file, changed differently on both sides. Git cannot know which version is right, so it stops and asks. That is not a failure — it is Git declining to silently throw away somebody's work.

People fear conflicts because the file looks alarming when one happens. It is worth seeing once, calmly, so it is boring the next time.
