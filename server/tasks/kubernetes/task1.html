Kubernetes: Many Copies, Kept Alive

What is Kubernetes?

One copy of an app on one machine is simple, and fragile. If the machine reboots the app is gone. If twice as many people arrive, it is slow. So real systems run several copies across several machines — and now somebody has to start them, notice when one dies, replace it, and share incoming visitors between the survivors.

Kubernetes is the program that does that somebody's job. You give it a file describing what you want — "three copies of this app, reachable on port 80" — and it keeps reality matching. A copy crashes at 3 a.m., Kubernetes starts another one. It does not ask, and it does not wait for you.

You describe the destination. Kubernetes handles the driving.

What you learned

  • A Deployment says how many copies should exist. Kubernetes keeps that number true, replacing any copy that dies.
  • Labels are how things find each other. If the selector does not match the labels, nothing is connected — and nothing tells you.
  • A Service is one stable address in front of copies that come and go.
  • Running is not ready. A readiness probe stops traffic arriving before the app can answer it.
