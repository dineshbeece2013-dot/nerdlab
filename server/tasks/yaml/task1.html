YAML Level 1

The Basics

You do not need to know anything to start this. By the end you will have written a real settings file, line by line, from an empty box.

So what is YAML?

Programs need settings. Which port to use, how many copies to run, whether to switch on extra logging. Somebody has to write those settings down in a file, and the program has to be able to read them back.

YAML is a way of writing settings that both people and computers can read. At its simplest it is one setting per line: a name, a colon, a space, then the value. 

service: checkout
port: 80
enabled: true

That is genuinely it. Three settings. You can read them without knowing a thing about programming — which is the whole point of YAML, and why almost every modern tool uses it. (You say it "YAM-ul", and nobody will mind either way.)

The catch is that YAML is fussy in a few places, and when you get one of those places wrong it does not politely tell you. It quietly does something else instead. Learning where those places are is most of the job.

You can now read and write a YAML settings file. That is a real skill, and you got it in four lessons.

What you learned this evening

  • A setting is a name, a colon, a space, and a value. The space after the colon is not optional.
  • YAML guesses what kind of value you wrote — text, whole number, decimal number, true/false, or nothing at all. Quote marks stop it guessing and keep your value as text.
  • Space at the start of a line means "inside". Two spaces per level, using the space bar, never the Tab key.
  • A dash and a space starts one item in a list.
  • Quote anything that only looks like a number. Version numbers, codes, anything with a leading zero. This is the habit that saves you at 3 AM.

That is enough to read most of the YAML you will ever meet — a Docker Compose file, a Kubernetes settings file, a GitHub Actions workflow. They all work exactly like this.
