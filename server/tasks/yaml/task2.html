3:14 AM — The Callout

Your phone wakes you at 3:14 in the morning. The checkout service — the part of the website that takes people's payments — has stopped working. Nobody broke the code tonight. Somebody broke the settings file, and that file is written in YAML.

You spent yesterday evening learning that exact file. Now you are the person who has to fix it. There are six faults. Traffic doubles at 6:00 AM.

Everything you need, from Part 1

  • A setting is a name, colon, space, value — service: checkout
  • Space at the start of a line means "this belongs inside the line above". Spaces only, never the Tab key.
  • A line starting with - is one item in a list.
  • YAML guesses what your value is: text, whole number, decimal, true/false, or nothing at all. Quote marks stop it guessing.
  • # starts a note that the computer ignores.

New here? Part 1 teaches all of this from scratch — but if the list above makes sense, you can start now.

Each fault works the same way: read what went wrong, fix the file in the box, and press the button. The page then reads your YAML for real, exactly the way a computer would, and shows you what it understood. Nothing is marked fixed unless it genuinely works.

What you learned tonight

  • Never press Tab. Only real spaces are allowed at the start of a line. Your screen draws a Tab like spaces; the computer does not.
  • YAML guesses what you meant. 1.10 becomes the number 1.1, and NO becomes false. Put quote marks around version numbers, codes, and anything that only looks like a number.
  • Where a line starts is the meaning. The position of the - decides whether you have two items or one.
  • Two ways to write several lines. | keeps the lines apart (use it for scripts). > joins them into one (use it for sentences).
  • Write shared settings once. &name labels a block, *name points at it, <<: pulls it in. Copying is how settings quietly drift apart.
  • --- splits one file into separate parts — and a label cannot reach across that line.

Those six rules are the whole game. The next YAML file you open — a Docker Compose file, a Kubernetes settings file, a GitHub Actions workflow — works exactly the same way.
